# Security policy

## Reporting a vulnerability

Report privately through GitHub: **Security → Report a vulnerability** on
this repository. A report made there, and the fix, stay private until the
fix is released. Please don't open a public issue, pull request or post
about it first.

Say what you found, how to reproduce it (a devnet script or the commands
you ran is ideal), what it lets an attacker do, and which commit or release
you tested. Test on the public testnet or your own devnet; never against
funds that aren't yours.

We acknowledge a report within three days and agree a disclosure date with
you: after the fix ships, or 90 days from the report, whichever is first.

## Scope and rewards

The testnet bug hunt ([docs/BUG-HUNT.md](docs/BUG-HUNT.md)) lists what is in
scope, the rules, and how findings are credited and rewarded. What the
review covers, the tools, and the findings so far are in
[docs/REVIEW.md](docs/REVIEW.md).

## Supported versions

The latest `v*-testnet` release and `main`. Older releases get no fixes:
upgrade.
