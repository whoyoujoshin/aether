# Mining from a browser or the desktop app

Two ways to mine `aether-testnet-1` without a node or a command line:

- **The explorer's Mine page** (`/mine`): scrypt in Web Workers on the
  visitor's CPU. Nothing to install.
- **Aether Pay desktop, Mine tab**: native Go scrypt in the app's local
  `walletapi`, for one of the wallet's own accounts. About 1.8 times the
  browser's speed per thread.

Both mine native submissions (`MsgSubmitPoW`), signed by the miner's own
ML-DSA-44 key. An accepted one pays the block reward to that account
(85%; the treasury cut is 15%) and counts as seat work. A miner becomes a
validator only with enough of the work and its own node with a registered
consensus key (`docs/SEAT-RULE.md`). Testnet AETH has no market value.

## What it costs the servers

Hashing costs the servers nothing: it runs on the miner's computer. Three
endpoints on the explorer serve the miners, and none of them grows the
load on aetherd with the number of miners:

| Endpoint | What | Cost |
|---|---|---|
| `GET /api/mine/work` | the latest block's height and hash, the difficulty, the recency window, the target | one gRPC read of the node every 3 s (`mineWorkTTL`), whoever asks; a short node outage serves the last good work |
| `GET /api/mine/account?addr=` | account number, sequence, balance | two cheap gRPC queries; 20 a minute per visitor |
| `POST /api/mine/submit {"tx": base64}` | relays a signed transaction | only one carrying exactly one native `MsgSubmitPoW`; 6 a minute per visitor, 300 a minute in all |

The chain takes one native submission a block, and difficulty retargets
as hash joins, so accepted submissions stay at about one a block however
many people mine. Each miner sends one find at a time: a find made while
another is on its way waits, and a newer one replaces it (a find stays
good for half the recency window, 30 blocks), so a miner doesn't race
itself into the same block. Confirmation reads `/api/tx?hash=` (the
browser) or `GetTx` by hash (the desktop), never a transaction search.

Behind Caddy the explorer sees 127.0.0.1, so the per-visitor limits key
on the last `X-Forwarded-For` entry, the one Caddy added.

## The browser miner

1. **Account.** Create one (24 words, shown once with a download, kept in
   the browser's storage) or recover one from its phrase. Anyone who can
   use that browser can spend what the account holds: testnet amounts only.
2. **Activate.** A new account exists on chain only once it receives
   funds, and it must exist to sign. One faucet drip (the Faucet page's
   proof-of-work flow) opens it.
3. **Mine.** Pick the threads (half the cores by default) and start. The
   page reads the work every 5 s and gives the threads a fresh header when
   the block it mines on is half the recency window old or the difficulty
   fell.

Code: `explorer-web/src/pages/Mine.tsx` and `explorer-web/src/mine/`,
using the TypeScript client's source (`clients/ts/src/{keys,tx,pow}.ts`).
Scrypt is `@noble/hashes`: about 2,000 hashes a second per thread in V8.

## The desktop Mine tab

`walletapi` serves `POST /api/mine/start {"name", "threads"}`,
`POST /api/mine/stop` and `GET /api/mine/status` (behind the app's
per-launch token, like every other route). It reads the work from
`--explorer`'s `/api/mine/work` (default the public explorer) and falls
back to the node over `--grpc`. It ships with the next desktop release.

## Shared code and tests

- `miner/`: header bytes, scrypt, targets, `Search`, `Work` (and its JSON)
  and the work cache; `miner/node` reads work over gRPC.
  `x/pow/miner_pkg_test.go` holds it to the keeper's `headerToBytes`,
  `meetsdifficulty` and `VerifyMiningHeader`.
- `clients/ts/src/pow.ts`: the same in TypeScript, plus `msgSubmitPoW`,
  tested against `clients/testdata/pow.json` (generated by
  `go test ./clients/vectors -update-vectors`), down to a signed
  submission's bytes and hash.
- On an `aether-rc-` devnet (difficulty about 20,000, 2 threads):
  - **browser, headless Chromium:** 3.75 kH/s; finds accepted and paid
    (the account went from 1,000 to 1,025.5 AETH after six), and a new
    account went from Create through its faucet drip to an accepted find
    in 10 s;
  - **desktop page against a real `walletapi`:** 6.68 kH/s, finds accepted.

## Deploying

No chain change. Build on a workstation with `scripts/prebuild.sh`, then
`PREBUILT=<folder> bash scripts/deploy-explorer.sh` on the seed: the
explorer binary gains `/api/mine/*` and the web build gains the Mine page.
Caddy already routes `/api/` to the explorer. The desktop tab arrives with
the next release tag.
