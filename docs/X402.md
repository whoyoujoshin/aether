# Standard x402 on Aether

Aether speaks standard [x402](https://github.com/x402-foundation/x402) v2:
the `exact` scheme on the network `cosmos:aether-testnet-1`. A buyer with
any x402 v2 client pays a 402 with a signed send of exactly the price. The
seller's facilitator checks it and broadcasts it. The payment is a normal
bank send that the payer signs and pays the fee for (zero on the
testnet), and the facilitator holds no key.

The scheme is specified in [x402/scheme_exact_cosmos.md](x402/scheme_exact_cosmos.md),
which covers any Cosmos SDK chain. It sits alongside Aether's own schemes
(`aether-memo`, `aether-prepaid`, `aether-pull`), which keep working
unchanged.

| Piece | Where |
|---|---|
| Verify and settle (Go) | package `x402` |
| Public facilitator | `cmd/facilitator`, on the seed at `https://explorer.157-245-252-221.sslip.io/facilitator` |
| Buyer (TypeScript) | `aether-chain-client/x402`: `ExactAetherScheme` for `@x402/core` / `@x402/fetch` |
| Seller (Go proxy) | `cmd/paywall`, on by default (`--exact=false` turns it off) |

## Paying

```ts
import { x402Client } from "@x402/core/client";
import { wrapFetchWithPayment } from "@x402/fetch";
import { AetherClient, Key } from "aether-chain-client";
import { ExactAetherScheme } from "aether-chain-client/x402";

const network = "cosmos:aether-testnet-1";
const key = Key.fromMnemonic(process.env.AETHER_MNEMONIC!); // an account the faucet funded
const client = new AetherClient({ rpc: "https://rpc.157-245-252-221.sslip.io" });
const pay = new x402Client()
  .register(network, new ExactAetherScheme(client, key))
  .setSpendControls({ allowedAssets: [{ network, asset: "uaeth", maxAmountPerPayment: "1000000" }] });

const res = await wrapFetchWithPayment(fetch, pay)("https://explorer.157-245-252-221.sslip.io/svc/hello/");
```

By default `x402Client` pays only USD stablecoins it knows, so allow
`uaeth` (or Aether's USDC denom) in its spend controls. Payments from one
key go one at a time: each is signed for the account's next sequence.

## Selling

**With `cmd/paywall`.** It already does this: each 402 also carries a
`PAYMENT-REQUIRED` header offering `exact`, and a `PAYMENT-SIGNATURE` is
settled through its `--grpc` node before the request is served. Only a
payment it broadcast itself is ever served on a retry (for example after
an upstream 5xx, or when the block came after the request gave up), and
only once.

**With any x402 v2 server SDK.** Point it at the public facilitator, for
example `new HTTPFacilitatorClient({ url: "https://explorer.157-245-252-221.sslip.io/facilitator" })`,
and offer:

```json
{ "scheme": "exact", "network": "cosmos:aether-testnet-1", "amount": "10000", "asset": "uaeth",
  "payTo": "aether1...", "maxTimeoutSeconds": 60, "extra": { "symbol": "AETH", "decimals": 6 } }
```

Blocks are about a minute apart, so `/settle` usually takes up to a minute.
The facilitator waits up to 80 seconds by default, or up to
`maxTimeoutSeconds` when that is longer, and `@x402/core`'s
`HTTPFacilitatorClient` gives up after 90. For more headroom, offer
`maxTimeoutSeconds: 120` and pass `timeoutMs: 150000` to the client. A
settle that times out reports `invalid_transaction_state` with the hash,
and the payment may still land.

For USDC, use `asset` `ibc/064D82A67318DD30F54A4E17B6E487C2864E8B075A5871D3ACAD7A7129F32C5C` (`wallet.TestnetUSDC`, 6 decimals).

## The facilitator

| | |
|---|---|
| `GET /supported` | `{"kinds":[{"x402Version":2,"scheme":"exact","network":"cosmos:aether-testnet-1","extra":{"feeDenom":"uaeth","feePayer":"payer"}}],"extensions":[],"signers":{}}` |
| `POST /verify` | `{x402Version, paymentPayload, paymentRequirements}` → `{isValid, invalidReason?, payer?}` |
| `POST /settle` | same body → `{success, errorReason?, payer?, transaction, network, amount?}`. It waits for the block (up to about a minute) |
| `GET /healthz` | 200 when its node answers |

It verifies, in this order:
- the message: one `MsgSend` of exactly the amount to `payTo`
- the signer: the sender's own key, in direct mode
- the fee payer and any timeout height
- the sequence
- the ML-DSA signature over the chain's `SignDoc` (simulation skips signatures)
- a simulation: balance, and gas within the transaction's limit

It settles a transaction at most once. Refusals use the spec's reasons:
the generic ones and `invalid_exact_cosmos_payload_*`.

Run your own with
`facilitator --listen :8403 --grpc <node>:9090 --chain-id aether-testnet-1`.
It handles at most `--max-concurrent` (32) payments at once.

## On the seed

`scripts/agentservices/install.sh` builds and runs it as
`aether-facilitator` (127.0.0.1:8403), and rebuilds the five paywalls,
which then accept `exact`. `caddy.sh` routes `/facilitator` to it. To
update both:

```bash
cd /root/aether-src && git fetch origin && git checkout origin/main
```

## Listings

- **Coinbase's Bazaar (CDP)** indexes only resources settled through
  Coinbase's own facilitator, which doesn't support Cosmos networks, so
  Aether services can't appear there for now.
- **The x402 Foundation** adds a new chain family in three PRs: the spec
  ([draft](x402/scheme_exact_cosmos.md)), then a reference implementation
  in one SDK, then the others. The spec PR is the first step towards
  listing.
